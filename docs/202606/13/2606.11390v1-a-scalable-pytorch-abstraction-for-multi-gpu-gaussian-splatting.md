## 摘要
高斯泼溅方法在真实世界的神经重建中越来越流行。然而，由于计算和内存的限制，它们通常在规模和分辨率上受限。我们提出了一种多GPU高斯泼溅方法，可以将重建扩展到更高的分辨率和更大的场景，同时抽象掉通常与模型分布相关的代码复杂性。为此，我们提出了一种PyTorch后端，通过CUDA统一内存和NVLink在GPU之间分布高斯参数和泼溅算子。由于分布发生在算子级别，模型代码不需要显式的跨设备通信。更广泛地说，该后端将多个GPU暴露为一个聚合的PyTorch设备，并支持其他PyTorch算子。我们展示了具有街道级细节的城市规模重建，包含超过10亿个高斯泼溅点，是目前最先进技术的25倍以上。

## Abstract
Gaussian splatting methods have become increasingly popular for neural reconstruction of the real world. However, they are often limited in scale and resolution due to compute and memory constraints. We present a multi-GPU Gaussian splatting approach that scales reconstruction to higher resolutions and larger scenes while abstracting away the code complexity typically associated with distributing a model. To accomplish this, we propose a PyTorch backend that distributes the Gaussian parameters and splatting operators across GPUs via CUDA unified memory and NVLink. Because distribution occurs at the operator level, the model code requires no explicit cross-device communication. More broadly, the backend exposes multiple GPUs as an aggregate PyTorch device and supports other PyTorch operators. We demonstrate city-scale reconstructions with street-level detail consisting of over 1 billion Gaussian splats, more than 25 times as many as the current state of the art.

### 2. 论文提出的方法论
- **核心思想**：构建一个名为 `torch-dgx` 的PyTorch后端，将多张GPU聚合为一个虚拟设备 (`dgx`)，利用CUDA统一内存和NVLink实现高效的跨设备数据访问，无需显式代码改动。
- **关键技术细节**：
    - **异步统一内存分配器**：用 `cudaMallocFromPoolAsync` 和 `cudaFreeAsync` 构建流序内存池，避免传统 `cudaMallocManaged` 的主机同步开销和性能衰减。
    - **分布式算子实现**：在算子内部将工作按输出维度（如行切片）或按像素/高斯分组分配到不同GPU，并发启动CUDA内核，内核间通过统一内存直接访问在其他GPU上的数据。不同算子间进行跨设备同步以避免读写竞争。
    - **高斯泼溅定制算子并行化**：
        - **球谐评估、投影等算子**：按高斯（per-Gaussian）分片，各GPU处理自己的高斯子集并生成所有相机的投影数据。
        - **光栅化与损失算子**：按像素/相机（per-pixel）分片。当相机数少于GPU数时，将图像进一步拆分为瓦片，并实现多GPU基数排序和合并路径算法以维持深度排序的独立性。
        - **反向传播**：梯度累积时，将设备域原子操作提升为系统域原子操作，以处理同一高斯点在多个瓦片/相机中可见时来自不同GPU的梯度贡献。
    - **空间局部性优化**：在致密化时使用Morton排序对高斯点进行三维空间排序，提升散射写访问的局部性（带来5-10%的提升）。
    - **集成与易用性**：挂载到PyTorch的dispatch机制，对用户暴露为新设备`"dgx"`，现有模型仅需将设备从`cuda`改为`dgx`即可在多GPU上运行。未实现的算子会平缓降级到CPU实现并发出警告。

### 7. 优点
- **极低的代码侵入性**：用户仅需更改设备字符串即可实现分布式训练/渲染，大幅降低分布式编程门槛。

- **高内存效率**：通过张量并行方式，能够训练远超单卡显存的模型，直接产出超大规模场景。

### 8. 不足与局限
- **恒定批量扩展性有限**：在模型极度分片（单图像分瓦片）时，由于跨GPU的随机读写和负载不均衡，加速比衰减明显，强于平方根但远低于线性。文中指出需更优的稀疏打包或辐射传输重构来改进。
- **依赖特定硬件**：高效运行依赖NVLink的高吞吐全互联通信，在无NVLink的普通PCIe多卡环境下可能表现不佳。
- **算子覆盖不完整**：目前支持的算子列表虽可满足高斯泼溅和基础扩散模型，但若模型调用未实现算子会回退到CPU执行，可能造成性能骤降。
- **未完全解决负载均衡**：光栅化等工作负载在不同GPU间可能不均，当前仅用Morton排序做了有限优化，未实现Grendel中的动态负载平衡。
- **对比方法单一**：实验主要与自身单GPU变体对比，未在相同数据集上直接比较Grendel等同期多卡方案的端到端吞吐与重建质量。
